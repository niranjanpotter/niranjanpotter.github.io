OAuth 2.0 JWT Bearer Token Flow & Zero-Downtime Certificate Rotation

Automating headless server-to-server integration without storing human passwords or refreshing interactive browser authorization codes.

Q1 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

Walk me through the exact steps of the Salesforce OAuth 2.0 JWT Bearer Flow.

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

1) Generate an RSA 2048-bit keypair using OpenSSL; 2) Upload the public digital certificate to the Salesforce Connected App; 3) Store the private key inside a MuleSoft JKS keystore; 4) At runtime, MuleSoft constructs a JWT assertion signed with RS256 containing issuer (Connected App Client ID), subject (Salesforce Integration User), audience (login.salesforce.com), and expiration; 5) POST assertion to /services/oauth2/token to receive an active access_token.

Q2 [PRODUCTION ARCHITECTURE] ⏱️ 3 min read

How do you rotate digital signing certificates without production API downtime?

🎯 HOW TO ANSWER (SENIOR ARCHITECT SCRIPT)

Salesforce Connected Apps support multiple concurrent digital certificates. In Phase 1, upload the new public certificate while leaving the old certificate active. In Phase 2, update the MuleSoft keystore with the new private key during a blue-green release. In Phase 3, verify successful token generation and delete the old certificate from Salesforce.
