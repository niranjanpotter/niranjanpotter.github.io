Q1 [SENIOR DEVELOPER] ⏱️ 2 min read Module SS

Why is wrapping an HTTP Request inside Until Successful without an error filter a production trap, and how do you handle retriable vs non-retriable errors?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"Until Successful retries ANY exception thrown inside its scope by default—including client errors like HTTP:BAD_REQUEST (400) or HTTP:UNAUTHORIZED (401). Retrying deterministic 4xx failures wastes vCore threads and delays failure responses. Wrap the HTTP Request inside a Try scope with On Error Continue for non-retriable 4xx errors (setting vars.nonRetriableError = true) so Until Successful exits cleanly, then raise the error downstream if vars.nonRetriableError is true."

💼Real-Time Project Example & Implementation
<until-successful maxRetries="3" millisBetweenRetries="2000">
  <try>
    <http:request config-ref="Backend_HTTP" path="/orders" />
    <error-handler>
      <on-error-continue type="HTTP:BAD_REQUEST, HTTP:UNAUTHORIZED, HTTP:FORBIDDEN">
        <set-variable variableName="fatal4xx" value="#[true]" />
      </on-error-continue>
    </error-handler>
  </try>
</until-successful>
⚠️Interviewer Cross-Question & Deep-Dive

Q: What HTTP status codes SHOULD be retried? A: Transient faults—HTTP:TIMEOUT, HTTP:CONNECTIVITY, HTTP:TOO_MANY_REQUESTS (429), and HTTP:SERVICE_UNAVAILABLE (503) / 502 / 504.

Q2 [SENIOR DEVELOPER] ⏱️ 2 min read Module SS

Explain the causal chain behind STREAM_MAXIMUM_SIZE_EXCEEDED on an HTTP Request or Transform, and how do you resolve it cleanly?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"Mule 4 uses repeatable streams with an in-memory buffer (512 KB by default) backed by disk overflow. STREAM_MAXIMUM_SIZE_EXCEEDED occurs when an HTTP connector or DataWeave script consumes a stream configured with non-repeatable-stream or exceeds a bounded maxInMemorySize without disk buffering enabled—or when an upstream API returns a multi-hundred-MB payload into an unstreamed buffer."

💼Real-Time Project Example & Implementation
<http:request-config name="Large_API">
  <http:request-connection host="api.internal" port="443" protocol="HTTPS" />
</http:request-config>
<!-- Use repeatable-file-store-stream with maxInMemorySize="2048" unit="KB" -->
⚠️Interviewer Cross-Question & Deep-Dive

Q: Does DataWeave @StreamCapable prevent this? A: Yes, streaming writers/readers process elements sequentially instead of materializing the full DOM tree in heap.

Q3 [DEVELOPER / ARCHITECT] ⏱️ 2 min read Module SS

How do you generate signed JWTs natively in Mule 4.13 / DataWeave 2.13 without external Java or Exchange libraries?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"DataWeave 2.13.0 (bundled with Mule 4.13.0 Edge, Oct 2026) added native dw::util::jwt::HMAC (HS256/384/512) and dw::util::jwt::RSA (RS256/384/512 using unencrypted PKCS#1 or PKCS#8 PEM private keys). You call JWT(header, payload, key, algorithm) directly inside Transform Message with zero custom Java dependencies."

💼Real-Time Project Example & Implementation
%dw 2.0
output application/json
import * from dw::util::jwt::RSA
---
{
  token: JWT({alg: "RS256", typ: "JWT"}, {sub: "erp-client", exp: 1796000000}, Mule::p("secure::jwt.pem"), "Sha256withRSA")
}
⚠️Interviewer Cross-Question & Deep-Dive

Q: Can dw::util::jwt::RSA read encrypted PKCS#8 keys with a passphrase? A: No—DataWeave 2.13 RSA expects an unencrypted PKCS#1 or PKCS#8 PEM private key stored safely in Secret Manager / Secure Properties.

Q4 [SENIOR DEVELOPER] ⏱️ 2 min read Module SS

Why did custom Java calls in DataWeave throw IllegalAccessException after upgrading to Mule 4.13 (Java 17), and how do you fix it?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"Mule 4.13.0 / DataWeave 2.13.0 enforces JDK 17+ Java Platform Module System (JPMS) package filtering by default. Unexported internal JDK packages (such as sun.* or private java.base internals) are blocked during DataWeave Java resolution. Refactor callers to use standard exported Java 17 APIs or native DataWeave modules."

💼Real-Time Project Example & Implementation
// Avoid: java!sun::misc::BASE64Encoder
// Use native DataWeave instead:
import * from dw::core::Binaries
---
toBase64(payload as Binary)
⚠️Interviewer Cross-Question & Deep-Dive

Q: Is --add-opens a good permanent fix? A: No—treat --add-opens only as a short-term migration bridge while removing internal JDK dependencies.

Q5 [ARCHITECT] ⏱️ 2 min read Module SS

After October 31, 2026, a CloudHub API suddenly started returning 502 Bad Gateway errors. What is the most likely root cause?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"On October 31, 2026, MuleSoft permanently terminated inbound TLS 1.0 and TLS 1.1 connections on all existing CloudHub 1.0 Dedicated Load Balancers (DLBs). If a DLB or CloudHub 2.0 Ingress forwards to an upstream Mule worker or partner endpoint pinning TLS 1.0/1.1 or incompatible ciphers, the handshake fails and returns 502 Bad Gateway."

💼Real-Time Project Example & Implementation
<tls:context name="Strict_TLS12_Context" enabledProtocols="TLSv1.2,TLSv1.3">
  <tls:key-store type="pkcs12" path="certs/api.p12" password="${secure::tls.pass}" />
</tls:context>
⚠️Interviewer Cross-Question & Deep-Dive

Q: Where else must TLS 1.2+ be verified? A: Both in Mule's HTTP Listener <tls:context> / tls-default.conf AND Runtime Manager's Upstream TLS setting.

⚠️Interviewer Cross-Question & Deep-Dive

Q7 [ARCHITECT / OPS] ⏱️ 2 min read Module SS

An Anypoint Runtime Fabric (RTF) app is stuck in NOT READY with 'tls: certificate required' or 'connection reset by peer' to us1.ingest.mulesoft.com. How do you diagnose it?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"First inspect pod events via kubectl describe pod and rtfctl status. 'tls: certificate required' or ingest resets usually mean either a corporate egress proxy is performing SSL MITM inspection on *.ingest.mulesoft.com (breaking mTLS), client certs expired, or duplicate imagePullSecrets exist in the namespace."

💼Real-Time Project Example & Implementation

kubectl describe pod <pod-name> -n <env-namespace>
⚠️Interviewer Cross-Question & Deep-Dive

Q: What changed in RTF 3.x rolling restarts? A: Use declarative spec.lifecycle.restartGeneration increments instead of manual pod deletions for zero-downtime restarts.

Q8 [SENIOR DEVELOPER] ⏱️ 2 min read Module SS

CloudHub workers are silently restarting with no application error log. What causes this and what changed in DataWeave 2.13.1?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"Silent worker restarts point to JVM OutOfMemoryError (OOM) killing the container before Mule's logger flushes—typically from loading huge payloads into memory, unbounded variables, or unstreamed transformations. DataWeave 2.13.1 (Nov 2026) also patched memory overhead on text/plain outputs and upgraded Jackson to 2.21.7."

💼Real-Time Project Example & Implementation
// Stream large CSV/JSON instead of building giant in-memory arrays
%dw 2.0
output application/ndjson deferred=true
---
payload map ((row) -> { id: row.id, total: row.qty * row.price })
⚠️Interviewer Cross-Question & Deep-Dive

Q: Should you just bump vCores first? A: Fix streaming, deferred=true, and variable cleanup first—otherwise larger vCores only delay the same leak.

Q9 [BEGINNER / DEVELOPER] ⏱️ 2 min read Module SS

Why do Anypoint Studio breakpoints miss when a local Process API calls a local System API?

⚡ Self-Test Mode Ready
✓ SENIOR MODEL ANSWER
🎯Verbal Pitch — Say It Like This (30 Sec)

"When both APIs run locally on the same machine, binding an HTTP Listener strictly to 127.0.0.1 vs 0.0.0.0, port collisions, or sending requests to an external CloudHub URL instead of localhost:<port> causes traffic to bypass your local debug session or hit the wrong network interface."

💼Real-Time Project Example & Implementation
# Local dev properties (config-local.yaml)
sapi:
  host: "localhost"
  port: "8082"
⚠️Interviewer Cross-Question & Deep-Dive

Q: How do you debug multiple Mule apps simultaneously in Studio or ACB? A: Use a Mule Application Launch Configuration referencing both projects and distinct HTTP ports (8081 / 8082).
