Q1 [DEVELOPER / SENIOR] ⏱️ 1 min read Module C

What are Platform Events? How do you subscribe in MuleSoft?

⚡ Self-Test Mode Ready
✓ ANSWER

Platform Events: Custom events you define in Salesforce and publish explicitly. Business events:

Order Closed, Payment Processed.

CDC (Change Data Capture): Automatic events fired by Salesforce on any record change — no

Apex/code needed. Includes changeType (CREATE/UPDATE/DELETE), changedFields.

Subscribe to Platform Event

REPLAYID MEANING

-1 New events only (default for initial deploy)

-2 All retained events (last 72 hours) — use on app restart

N Replay from specific event ID forward

🎯🎯 Interview Pitch - Say It Like This (30 Sec)
"We implement event-driven architectures between Salesforce and MuleSoft using Platform Events and Change Data Capture. In MuleSoft, we subscribe using the Replay Channel Listener backed by persistent ObjectStore storage to save the Replay ID, guaranteeing at-least-once delivery and zero event loss even during downstream system downtime or planned maintenance."
💼💼 Real-Time Project Example

Project: Commercial Banking — Real-Time Order Status Notification.

Problem: Traditional scheduled polling every 2 minutes was too slow for customer notifications and wasted 70,000 API calls daily.

What I Did: Subscribed to Salesforce `Order_Status_Event__e` Platform Events via MuleSoft Replay Channel Listener, routing events through Anypoint MQ for async processing.

Result: Achieved end-to-end event notification latency of under 400ms while eliminating 100% of polling API calls.

Q2 [DEVELOPER / SENIOR] ⏱️ 1 min read Module C

What is event retention? What if Mule app is down >72 hours?

⚡ Self-Test Mode Ready
✓ ANSWER

Salesforce Platform Events and CDC are retained for 72 hours. If MuleSoft subscriber restarts with

replayId="-2" , it receives all events from the last 72 hours — nothing is lost for normal downtime.

If downtime exceeds 72 hours: those events ARE permanently lost. Mitigation: also publish to

Anypoint MQ (default 4–7 day retention, configurable up to 14 days; 10 MB max message payload) as durable backup fan-out for critical events. Or implement a Scheduler that

queries Salesforce directly for records modified during the downtime window using LastModifiedDate

> :lastRun watermark.

Q3 [DEVELOPER / SENIOR] ⏱️ 1 min read Module C

How do you handle duplicate Platform Events (at-least-once delivery)?

⚡ Self-Test Mode Ready
✓ ANSWER

Salesforce uses at-least-once delivery — duplicates are possible. Implement idempotency with

ObjectStore:

Idempotency Pattern

// 1. Extract Replay ID or business key from event

// 2. Check ObjectStore

os:contains(key=replayId, objectStore=idempotency-store)

// EXISTS → skip and ACK

// NOT EXISTS → process → os:store(key, TTL=72h) → ACK

Use acknowledgementMode="MANUAL" so ACK only happens after successful ObjectStore write +

processing.
