Q18 [DEVELOPER / SENIOR] ⏱️ 1 min read Module U

An exception arose at System layer and I want that error message to propagate to Experience

⚡ Self-Test Mode Ready

layer. How?

✓ ANSWER

Use on-error-propagate at each layer. In the SAPI: catch the error → build standardized error

payload → re-throw using . In the PAPI: same pattern — on-error-propagate re-throws the error

upward. In the XAPI: on-error-propagate catches it → formats into the standard HTTP error response

format with correct status code.

The key: keep the error payload consistent at every layer. Use a standard error schema {correlationId,

errorCode, message, layer} so XAPI always knows what to expect regardless of which layer the error

originated from.

I design a centralized Global Error Handler using On Error Propagate for unexpected system exceptions to guarantee transaction rollbacks and standardized HTTP 5xx responses, while using On Error Continue inside Try scopes for anticipated business fallbacks—always ensuring correlation IDs and structured JSON schemas are propagated."

Problem: Unhandled downstream 503 errors and connection timeouts were returning generic, unhelpful HTML error pages to frontend clients with zero traceability.

What I Did: Created an enterprise global error handler mapping HTTP:CONNECTIVITY, HTTP:TIMEOUT, and MULE:EXPRESSION to RFC 7807 Problem Details JSON, preserving X-Correlation-ID across all layers.

Q19 [DEVELOPER / SENIOR] ⏱️ 1 min read Module U

System API is taking too long to respond (timeout). How do you fix it from XAPI's perspective?

⚡ Self-Test Mode Ready
✓ ANSWER

Three approaches depending on requirements:

1.Increase responseTimeout: On the HTTP Request config in PAPI that calls SAPI, increase

responseTimeout value. Quick fix but doesn't solve the root cause.

2.Async pattern (preferred): XAPI returns 202 Accepted immediately. PAPI publishes request to

Anypoint MQ. MQ consumer calls SAPI when it's ready. XAPI provides a polling endpoint or callback

URL for the result.

3.Retry with Until Successful: Wrap the SAPI call in Until Successful — if timeout occurs, retry up to

N times with a delay. Catch MULE:RETRY_EXHAUSTED → return 503 with Retry-After header to caller.

Q20 [DEVELOPER / SENIOR] ⏱️ 1 min read Module U

How do you implement CI/CD for MuleSoft? What Maven commands do you use?

⚡ Self-Test Mode Ready
✓ ANSWER

In our Enterprise Architecture: GitHub Actions triggers on push to any environment branch. Pipeline stages:

1.mvn clean compile — compile all source files
2.mvn test — run MUnit tests, generate coverage report
3.mvn sonar:sonar — upload coverage to SonarQube, enforce quality gate
4.mvn package — build deployable JAR artifact
5.mvn deploy -DmuleDeploy (with Mule Maven Plugin) — deploy to CloudHub target environment

Secrets (CloudHub credentials, connected app keys) stored in GitHub Secrets, passed as environment

variables to Maven. Deployment targets vary by branch: develop→sandbox, qa-branch→qa,

main→production. Maven Parent POM / BOM centralizes all shared plugin and connector versions — every enterprise API inherits from it.

What is the p() function in DataWeave? What is lookup()?

⚡ Self-Test Mode Ready
✓ ANSWER

p() function: Reads a value from a properties file (application properties, config YAML, Secure

Properties). Used to access configuration without hardcoding.

DataWeave — p() to read properties

DWL 
%dw 2.0
output application/json
---
{ "appName": p('app.name'), "apiKey": p('secure::api.key') }

lookup() function: Invokes a Mule flow by name from within a DataWeave expression and returns its result. Can only call flows — not sub-flows.

DataWeave — lookup() to call a flow

DWL 
%dw 2.0
output application/json
---
{ result: lookup('validateAddressFlow', {address: payload.address}) }

flattenNested arrayOne-level-flattened arrayYou have [[1,2],[3,4]] and want [1,2,3,4]

DataWeave — flatten vs flatMap

DWL

Q5 [DEVELOPER / SENIOR] ⏱️ 1 min read Module U

What is zip() function? How do you merge two arrays?

⚡ Self-Test Mode Ready
✓ ANSWER

zip() combines two arrays element-by-element into an array of pairs (arrays of 2 elements each).

DataWeave — zip() and flatten to merge

DWL 
%dw 2.0
output application/json
---
// zip two arrays:
["Alice","Joe"] zip ["Integration Engineer", "Lead"]
// Output: [["Alice","Integration Engineer"],["Joe","Lead"]]
// Merge two arrays into one flat array:
import * from dw:-core:-Arrays
var a1 = ["a","b"]
var a2 = ["c","d"]
---
flatten([a1, a2])
// Output: ["a","b","c","d"]

DWL 
%dw 2.0
output application/json
var numbers = [1, 2, 3, 4]

{

product: numbers reduce ((item, acc = 1) -> acc * item),   // 24

maxSalary: salaries reduce ((item, acc = 0) -> if (item > acc) item else acc) // 70000
}

Q8 [DEVELOPER / SENIOR] ⏱️ 1 min read Module U

What is match vs matches? What is read() vs readUrl()?

⚡ Self-Test Mode Ready
✓ ANSWER

DataWeave — match vs matches

// match: returns array of capture groups from regex match

"me@mulesoft.com" match(/([a-z]*-@([a-z]*-.com/)

// Output: ["me@mulesoft.com", "me", "mulesoft"]

// matches: returns boolean — does entire string match?

"admin123" matches /a.*\d+/ // true

"admin123" matches /^b.+/ // false

DataWeave — read() vs readUrl()

// read(): parses a string or binary as a specific MIME type

read('{ "Hello": "World" }', 'application/json')

// Output: parsed JSON object

// readUrl(): reads from URL (including classpath)

readUrl("classpath:--config/mapping.json", "application/json")

// Reads from src/main/resources/config/mapping.json
