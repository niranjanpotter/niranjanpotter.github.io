Q1 [ARCHITECT / AI LEAD] ⏱️ 3 min read Module JJ

What is Anypoint Topic Center and how do you expose MuleSoft APIs as Salesforce Agentforce Actions?

⚡ Self-Test Mode Ready
✓ ANSWER
🎯 HOW TO ANSWER (VERBAL SCRIPT)

"In the 2026 Salesforce + MuleSoft architecture, Anypoint Topic Center serves as the governance gateway that transforms traditional System and Process APIs into autonomous actions that Salesforce Agentforce can invoke dynamically. Instead of hardcoding Apex callouts or manual flow actions, Agentforce reasons over API definitions using LLM agents. To make an API an Agentforce Action, we publish an OpenAPI Specification (OAS 3.0 or 3.1) into Anypoint Exchange enriched with x-sfdc metadata annotations. These annotations specify the Agent Topic, the required user permissions, natural-language parameter descriptions, and instructions telling the LLM when and why to invoke the endpoint. Topic Center registers this asset in the Salesforce API Catalog, allowing the Agentforce reasoning engine to bind to it at runtime with full zero-trust OAuth 2.0 token propagation."

💻 OAS 3.0 AGENTFORCE ANNOTATION SPECIFICATION
paths:
  /billing/accounts/{accountId}/invoices:
    get:
      summary: Retrieve Customer Invoices for Utility Billing
      description: Returns unpaid and historical utility invoices for a customer account.
      x-sfdc:
        topic: CustomerBillingSupport
        instruction: "Use this action when a customer asks about past due balance, current bill amount, or invoice PDF copies."
        is-agent-action: true
      parameters:
        - name: accountId
          in: path
          required: true
          description: "10-digit enterprise customer account number"
          schema:
            type: string
Q2 [ARCHITECT / AI LEAD] ⏱️ 3 min read Module JJ

What is the Model Context Protocol (MCP) Connector in MuleSoft and how does it connect AI Agents to enterprise APIs?

⚡ Self-Test Mode Ready
✓ ANSWER
🎯 HOW TO ANSWER (VERBAL SCRIPT)

"The Model Context Protocol (MCP) is the open enterprise standard enabling AI foundation models (such as Claude, GPT-4, and Gemini) to securely discover and invoke tools, context, and prompts hosted by external servers. MuleSoft's MCP Connector acts in two modes: as an MCP Server Bridge and as an MCP Client Connector. As a Server Bridge, MuleSoft wraps enterprise backends (SAP, ServiceNow, AWS) and exposes their operations as standardized MCP Tools over Server-Sent Events (SSE) or stdio transports. The agent queries the MCP tools/list endpoint, receives structured JSON Schemas of all available MuleSoft flows, and executes them with parameterized arguments. The MCP Connector enforces mutual TLS, API Manager rate limiting, and client-id enforcement, ensuring enterprise data boundaries are never bypassed by autonomous agents."

Q3 [SENIOR DEVELOPER] ⏱️ 3 min read Module JJ

How does MuleSoft Model Proxy optimize LLM costs using Semantic Caching and fallback routing?

⚡ Self-Test Mode Ready
✓ ANSWER
🎯 HOW TO ANSWER (VERBAL SCRIPT)

"In enterprise AI architectures, calling commercial LLMs directly from application code creates runaway token expenses, latency spikes, and single-provider lock-in. MuleSoft's Model Proxy acts as an AI Gateway layer deployed between consumers and LLM providers. It exposes a single OpenAI-compatible endpoint but executes three critical capabilities: First, Semantic Caching: queries are vectorized and compared against an in-memory vector database. If a semantically equivalent query was answered recently (cosine similarity > 0.92), the cached response is returned in <15ms with zero token cost. Second, Fallback & Circuit Breaking: if OpenAI experiences high latency or rate limits (HTTP 429), the proxy automatically reroutes the prompt to Azure OpenAI or Google Gemini. Third, Token Wallets & Quotas: enforcing team-level token consumption budgets to prevent bill shocks."

Q4 [ARCHITECT / AI LEAD] ⏱️ 3 min read Module JJ

How do you define and orchestrate autonomous multi-agent networks in MuleSoft using agent-network.yaml?

⚡ Self-Test Mode Ready
✓ ANSWER
🎯 HOW TO ANSWER (VERBAL SCRIPT)

"Autonomous Agent Networks represent the paradigm where multiple specialized agents collaborate to solve complex business transactions (e.g., a Customer Dispute Agent collaborating with a SAP Billing Agent and a Fraud Detection Agent). In MuleSoft, we declare these networks declaratively using agent-network.yaml. This manifest defines the broker runtime, registered member agents, communication channels (event-driven Anypoint MQ or synchronous HTTP/2), shared state memory, and escalation rules. The Anypoint Agent Fabric broker parses this manifest, manages inter-agent messaging, handles handoffs between agents, and enforces governance boundaries so no agent can exceed its granted tool scope."
